The Burden of Administration

Running a standard website is a matter of uptime; running an `.onion` service is a matter of survival. Advanced OPSEC for Onion Service Admins goes far beyond basic server hardening. If you are operating a darknet marketplace, an anonymous whistleblower drop, or a secure forum, you are actively hunted by state-level adversaries and rival threat actors.

A single misconfiguration in your web stack will result in your server revealing its true IP address. In 2026, administrators must adopt a paranoid, defense-in-depth architecture that assumes the web application itself will eventually be compromised.

The Principle of Isolation

Never run your Tor daemon, your database, and your web server on the same physical or virtual machine.

  • The Proxy Gateway: The server that hosts your `.onion` keys (The Tor Gateway) should do nothing else. It receives incoming Tor traffic and proxies it through a secure, encrypted tunnel (like WireGuard) to a completely separate, hidden backend server.
  • Database Segregation: Your SQL database must live on a third, isolated server that only accepts connections from the internal IP of your web application server.
  • Why this Matters: If a hacker finds an exploit in your forum software, they compromise the web server. But because the `.onion` keys and the database are on different, firewalled machines, the attacker cannot steal your darknet identity or the user data.

Defeating Server-Side Request Forgery (SSRF)

SSRF is the most lethal vulnerability for a hidden service. In an SSRF attack, a hacker tricks your web application into making an outbound HTTP request to an IP address the hacker controls.

The Firewall Kill Switch

If your server makes that outbound request over the clearnet, your true IP is logged by the hacker. To prevent this, you must configure strict `iptables` or `ufw` rules that block all outbound traffic from the web server user. The server should only be allowed to communicate over localhost to the Tor daemon. It must be physically impossible for the server to ping the open internet.

Operational Hygiene

The weakest link is the human administrator. Never SSH into your infrastructure from your home network; only administer servers via Tor Hidden Services. Purchase all infrastructure using Monero (XMR) and burner identities. Maintain offline, encrypted backups of your `hs_ed25519_secret_key`—if you lose this, your domain is dead. For definitive technical guidelines, constantly monitor the Tor Project Security Advisories.
